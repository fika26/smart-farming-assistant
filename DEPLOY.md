# Deploy for free (Vercel + Render)

| Part | Where | Free plan |
|---|---|---|
| Frontend (Next.js) | **Vercel** Hobby | Free, personal/non-commercial use |
| Backend (FastAPI) | **Render** free web service | Free, no card; sleeps after 15 min idle |

Total cost: ₹0. Time: about 20 minutes.

---

## 1. Put the code on GitHub

Create an empty repository on github.com (private is fine), then from the unzipped `repo` folder:

```bash
git init
git add .
git commit -m "Smart Farming Assistant v6"
git branch -M main
git remote add origin https://github.com/<your-username>/smart-farming-assistant.git
git push -u origin main
```

`.env` and `.env.local` are git-ignored, so no secrets are pushed.

## 2. Backend on Render

1. Sign in at https://render.com with GitHub.
2. **New → Blueprint** → choose the repository. Render finds `render.yaml`.
3. It asks for the values marked `sync: false`:
   - `CORS_ORIGINS`: leave empty for now (every `*.vercel.app` URL is already allowed by `CORS_ORIGIN_REGEX`).
   - `AI_API_KEY`: optional. For real AI answers, create a free key at https://aistudio.google.com/apikey (Gemini). Leave empty to use the built-in rules.
4. **Apply**. The first build takes 3–5 minutes.
5. Copy the service URL, e.g. `https://smart-farming-api.onrender.com`, and open
   `https://smart-farming-api.onrender.com/api/health`. You should see `{"status":"ok",...}`.

`JWT_SECRET` and `INGEST_API_KEY` are generated by Render automatically.

## 3. Frontend on Vercel

1. Sign in at https://vercel.com with GitHub → **Add New → Project** → import the repository.
2. **Root Directory**: click *Edit* and choose `frontend`. Framework is detected as Next.js.
3. **Environment Variables**: add
   `NEXT_PUBLIC_API_BASE_URL` = `https://smart-farming-api.onrender.com/api` (your Render URL + `/api`).
4. **Deploy**. You get a URL like `https://smart-farming-assistant.vercel.app`.

If you later use a custom domain, add it to `CORS_ORIGINS` in Render (Environment tab).

## What to expect on the free plans

- **First visit after a quiet spell takes up to a minute.** Render stops the backend
  after 15 minutes without traffic. The app shows a "Starting the farm server…" bar and
  retries on its own, so nobody sees an error.
- **Data resets when the backend sleeps.** Readings are simulated and accounts live in
  memory, so accounts created with *Create account* disappear on restart. The demo
  account always works. For permanent accounts and real sensor history, connect a
  database later (Supabase has a free tier; `backend/app/repositories/supabase.py` is the stub).
- **Keeping it awake for a demo.** Before a presentation or judging, open the site once
  about two minutes early. To keep it awake all day, create a free monitor at
  https://cron-job.org that requests `/api/health` every 10 minutes. One always-on
  service uses about 744 of Render's 750 free hours a month, so only do this for one service.
- **Vercel Hobby is for non-commercial use.** Fine for a hackathon, college or portfolio
  project. A commercial launch needs Vercel Pro, or host the frontend on Render too.

## Updating

Push to `main`. Vercel and Render both redeploy automatically.

## Troubleshooting

- **"Cannot reach the backend" and it doesn't recover after a minute.** Check
  `NEXT_PUBLIC_API_BASE_URL` in Vercel ends with `/api`. After changing it, redeploy,
  because the value is baked in at build time.
- **Browser console shows a CORS error.** Your frontend isn't on `*.vercel.app` (e.g. a
  custom domain). Add the exact origin to `CORS_ORIGINS` in Render.
- **Render build fails on Python.** `PYTHON_VERSION` is pinned to 3.11.9 in `render.yaml`. Keep it.
- **AI answers say "Offline mode".** `AI_API_KEY` isn't set, or the key is invalid. Check Render → Logs.
